# Star2D Remote — guide for AI assistants

You were given this link because the user wants you to build or edit a game in **Star2D**, a 2D game engine and editor that runs on **their Android phone**. You control it through tools that this server relays to the phone.

Server: `{{SERVER}}`

## How you connect

The user's app shows a private connector URL. It looks like this:

- **MCP (Streamable HTTP):** `{{SERVER}}/mcp/<secret>` — add it as a custom connector (Claude: Settings → Connectors → Add custom connector; no login needed, the secret in the URL is the key).
- **Plain HTTP, for AIs that can make web requests but not MCP:** `POST {{SERVER}}/api/<secret>/<tool>` with the tool arguments as the JSON body. The answer is JSON: `{"content":[...],"isError":false}`. Example: `POST {{SERVER}}/api/<secret>/status` with body `{}`.

Treat the URL like a password. Never print it back to other people.

## Rules that matter

1. **The engine only exists on the phone.** Never try to compile, run or test the game in your own sandbox or server. Use the tools: `build`, `run_game`, `screenshot`, `game_state`, `run_test`.
2. **The app must stay open and visible.** If a tool answers `app_not_connected` or `timeout`, tell the user (in their language): *"Open the Star2D editor now and keep it on screen. I work in the background."* Then call `wait_for_app` until it connects. Android pauses apps in the background, so split-screen next to the chat is ideal.
3. **Read the docs first.** Call `read_docs` with no topic for the index, then read the topics you need. They are generated by the app, so they always match its version (every element type and property, events, blocks, joints, assets, physics units, recipes).
4. **Show a plan.** Call `set_plan` (title + tasks) before you start, `update_task` as each task starts/finishes (use `updates` to batch), and `finish_work` at the end. The user watches the plan live and cannot edit while you work (they can still look around, and can press *Take control*).
5. **Batch.** `elements`, `events`, `files`, `variables`, `joints` take lists of operations. One call can build a whole scene. The free server has a daily call budget shared by all users.
6. **Blocks first.** Game logic is visual blocks (the user edits them on the phone). Use `block_catalog` + `events` with `blocks`. Create missing blocks or categories with `define_blocks`. Use raw Java only when no block can express it.
7. **Make your own assets.** `create_image` (pixel sprites, shapes, gradients), `create_sound` (synthesized effects). No uploads needed.
8. **Verify before you say it works.** Build, run, screenshot, read state, test with `run_test`. Fix problems and repeat.

## A good first message to the user

Before your first tool call say (in the user's language): *"Open the editor now and keep it open — Claude is working in the background."* Then `status` → `read_docs` → `set_plan` → work → `run_test` → `finish_work`.

## Privacy

This server stores no project files. It relays messages between you and the phone, keeps a tiny per-day call counter, and deletes even that automatically when the phone has been disconnected for a while.
